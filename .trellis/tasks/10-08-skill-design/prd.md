# Agent 技能体系：主技能 + 子技能设计

> 技术方案见同目录 [`design.md`](design.md)；一手来源调研（逐条带出处）见 [`research.md`](research.md)。
> 状态：**设计方案已出，待用户拍板 SD-1～SD-5**（见 design.md 第七节）。

## 背景

CLI 已交付到 M2（14 条命令，Node 22/24 双版本门禁 112/112 全绿），但**尚无 Agent 技能**：
`docs/PRD.md` 5.5 与 D6 已经把 SKILL.md 的规约写好，PRD 附录 A 也给了一份骨架，
M4 里程碑（PRD 第 9 节）正对应这件事 —— 未落地。

用户要求：**未实现的功能暂不做**（`report`／`export`／`import`），改为**新增技能**，
并采用「**主技能 + 子技能**」的组织方式。

## 范围内

- 设计并落地一套 Agent 技能：主 `SKILL.md`（路由 + 全局纪律 + 取契约）+ `reference/*.md` 子技能。
- 覆盖**已实现的 14 条命令**；`report`／`export`／`import` 对应的内容**不写**（未实现）。
- 部署落点与文档（PRD 5.5.2 要求"建议提供各客户端的部署示例"）。

## 范围外

- 任何 CLI 功能开发（`report`／`export`／`import` 明确不做）。
- 改写 CLI 的错误码／命令面（技能必须适配现状，不是反过来）。
- 把技能复制进各客户端目录并实测触发（取决于用户实际使用的客户端）。

## 验收标准

- **AC-1（C1/C2）** `test/gates.test.ts` 新增一条门禁：技能文本中**不出现**错误码字面量、
  枚举值清单、以及 `--flag <...>` 形态的参数声明。把 D6 从自觉变成可执行断言。
- **AC-2（C1）** 技能中出现的每条 `workreport` 调用，其参数都能在 `describe` 输出里找到同名 flag。
- **AC-3（C3/C4/C5/C6/C7）** 逐条可指认：C3–C6 在主技能或某子技能中有明确表述；
  C7 处仅引用 `PRD 5.2.9` 而无分组/排序规则复述。
- **AC-4** 冷启动验收：仅凭 `SKILL.md` + `describe` 输出（无其它项目上下文）的 Agent，
  能按编排纪律完成 7 个典型任务；判据是**纪律不被违反**，不是"命令跑通"。
- **AC-5** 双版本 `npm run verify` 全绿（技能是纯文档，不应影响构建；若加了门禁用例则数字上升）。
